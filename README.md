# WGB Hotel & Restaurant — Интеграция ИИ-агента с OpenAI API

Полнофункциональное решение по внедрению интеллектуального виртуального консультанта на базе официального OpenAI API в существующий сайт отеля WGB.

---

## 🌟 Возможности системы

1. **Плавающий виджет ИИ-агента:**
   - Расположен в правом нижнем углу сайта, идеально выдержан в фирменном стиле WGB (`#0b2b26`, `#235347`, `#8eb69b`, `#daf1de`, `#f5f4ed`).
   - Адаптивен: комфортно работает на компьютерах, планшетах и смартфонах.
   - Быстрые действия: «Забронировать номер», «Рассчитать групповое проживание», «Узнать об услугах отеля», «Организовать деловую поездку», «Связаться с менеджером».
   - Индикатор формирования ответа (typing indicator), сохранение истории сессии, возможность свернуть и закрыть чат.

2. **Интеграция с официальным OpenAI API:**
   - Использует официальный SDK `openai` и Responses/Chat Completions API.
   - Поддерживает вызовы инструментов (Function Calling / Tool Calling):
     - `calculate_group_booking`: автоматический точный расчёт стоимости проживания и питания по тарифам отеля (30 000 ₸ за номер/ночь, питание от 4 000 до 15 000 ₸).
     - `create_booking_lead`: сбор и регистрация структурированных заявок от клиентов.
     - `request_human_manager`: эскалация диалога на живого менеджера с фиксацией контактов.
     - `get_hotel_services_info`: поиск по динамической базе знаний отеля.
   - Встроенный интеллектуальный Fallback: при отсутствии ключа или временной недоступности API сервис не падает, а отвечает из встроенной базы знаний отеля.

3. **Защищенная административная панель (`/admin`):**
   - Авторизация по паролю администратора (по умолчанию: `admin12345`).
   - Настройка OpenAI API Key без изменения программного кода (ключ хранится строго на сервере, в браузер передается только маска `sk-...xxxx`).
   - Кнопка **«Проверить подключение»** с реальной валидацией через тестовый запрос к OpenAI.
   - Выбор модели (`gpt-4o-mini`, `gpt-4o`, `gpt-3.5-turbo`), параметров `Temperature` и `Max Output Tokens`.
   - Тумблер мгновенного включения / отключения ИИ-агента.
   - Редактор приветственного сообщения и системного промпта (System Prompt) с кнопкой сброса к базовому регламенту.
   - Управление базой знаний (Knowledge Base): добавление, редактирование и удаление статей по номерам, ресторану, правилам заезда (14:00/12:00), закрывающим документам, трансферу и удобствам.
   - Управление заявками (Leads): просмотр, смена статусов, экспорт в CSV, повторная синхронизация с CRM.
   - Просмотр диалогов с поддержкой политики хранения данных и удаления персональных данных (GDPR / закон о ПД).
   - Модуль CRM Bitrix24: отправка лидов через входящий REST вебхук (`crm.lead.add.json`).

4. **Аналитика:**
   - Количество начатых диалогов и уникальных посетителей.
   - Количество сформированных заявок и конверсия диалогов в лиды (%).
   - Популярные темы и вопросы гостей.
   - Востребованные услуги отеля.
   - Запросы на связь с менеджером.
   - Расход токенов (Prompt / Completion) и автоматический расчет затрат в долларах США ($).

## 🚀 Быстрый старт

### 1. Установка зависимостей

```bash
npm install
```

### 2. Запуск сервера

Для запуска в стандартном режиме:
```bash
npm start
```

Для запуска с автоматической перезагрузкой при изменении файлов:
```bash
npm run dev
```

Сервер запустится по адресу: **`http://localhost:3000`**

- **Главная страница сайта:** [http://localhost:3000](http://localhost:3000)
- **Панель управления (Admin):** [http://localhost:3000/admin](http://localhost:3000/admin) (Пароль: `admin12345`)

## ⚙️ Настройка OpenAI API Key

Вы можете подключить API-ключ двумя удобными способами:

### Способ 1: Через административную панель (Без перезапуска и без правок кода)
1. Откройте в браузере [http://localhost:3000/admin](http://localhost:3000/admin).
2. Введите пароль `admin12345` и перейдите во вкладку **«OpenAI & Настройки»**.
3. В поле **«OpenAI API Key»** вставьте ваш ключ (начинается с `sk-...`).
4. Нажмите **«⚡ Проверить подключение»** — система выполнит тестовый запрос к OpenAI и отобразит статус.
5. Нажмите **«Сохранить настройки OpenAI»**. Ключ запишется в защищенное серверное хранилище.

### Способ 2: Через файл `.env`
Создайте или отредактируйте файл `.env` в корне проекта:
```env
PORT=3000
OPENAI_API_KEY=sk-proj-ваш_настоящий_ключ_openai
OPENAI_MODEL=gpt-4o-mini
ADMIN_PASSWORD=admin12345
BITRIX24_WEBHOOK_URL=
DATA_RETENTION_DAYS=30
```

## 💼 Настройка CRM Bitrix24

1. В вашем Битрикс24 перейдите в раздел **Разработчикам → Другое → Входящий вебхук**.
2. В правах доступа выберите модуль **CRM**.
3. Скопируйте полученный вебхук (например, `https://your-domain.bitrix24.ru/rest/1/xxxxxxxx/`).
4. Вставьте его в админ-панели во вкладке **«OpenAI & Настройки»** в поле **«Входящий вебхук Bitrix24»** и нажмите **«🔍 Проверить вебхук»**.
5. Все новые заявки, создаваемые клиентами в чате, будут автоматически регистрироваться в Битрикс24 в виде лидов со всеми параметрами поездки и резюме диалога.

## 🔒 Безопасность и архитектура

- **Защита API-ключа:** Ключ никогда не отправляется на фронтенд, не попадает в git и доступен только изолированному Node.js бэкенду.
- **Ограничение частоты запросов (Rate Limiting):** Защита от спама и перегрузки через `express-rate-limit` (до 30 сообщений в минуту с одного IP).
- **Защита от XSS и инъекций:** Все пользовательские данные экранируются при выводе и санитизируются.
- **Политика конфиденциальности (GDPR):** Кнопка мгновенного удаления персональных данных по запросу клиента, а также настраиваемый авто-клининг старых сессий.
- **Логирование:** В логах отображаются только маршруты, статус-коды и тайминги без раскрытия ключей или конфиденциальных параметров.

## Проверка и доработка ассистента (27 октября 2026)

Результаты пяти сценариев и ограничения проверки: [docs/assistant-evaluation.md](docs/assistant-evaluation.md).

### GitHub Pages и сервер — разные режимы

На GitHub Pages Node.js API не исполняется. Без внешнего сервера виджет работает
как **справочный помощник по демонстрационной базе**, а не как подключённая модель.
Используются `assistant-policy.js` и публичный `assistant-knowledge.json`.
Контакты в этом режиме не собираются, заявки не отправляются.

Для подключения развёрнутого Node.js-сервера укажите в `assistant-config.js`
публичный HTTPS-адрес API, например `apiBase: 'https://your-backend.example/api'`.
Не помещайте в этот файл ключ OpenAI, пароль администратора или вебхук CRM.
Сервер запускается `npm start`; секреты настраиваются только на сервере.
Само наличие серверного кода в репозитории не означает, что API уже развёрнут.

### База данных и тарифы

Сохраняется существующее хранилище `data/database.json`. Добавлены `schemaVersion: 2`
и раздел `pricing` (статус `demo` или `verified`, стоимость номера, максимум гостей,
тарифы питания). Существующие настройки, статьи, заявки и диалоги сохраняются при загрузке.
Неподтверждённые записи считаются демонстрационными. Старые пользовательские промпты
сохраняются, обязательные правила точности добавляются к ним при каждом запросе.

Ассистент, серверный калькулятор и калькулятор страницы получают тарифы из этой базы.
`GET /api/agent/knowledge` возвращает только публичные статьи и тарифы.
`GET /api/admin/pricing` и `PUT /api/admin/pricing` позволяют читать и менять тарифы
с действующим `X-Admin-Token`. Поля `roomRate` и `meals.*.rate` — числа в тенге,
`maxGuests` — целое число. Статьям доступны `status` и `isPublic`.
Присваивайте статус `verified` только после проверки фактических условий отеля.

Для отдельного экземпляра хранилища или постоянного диска задайте `WGB_DB_PATH`.
Секреты и контакты нельзя размещать в публичном репозитории.
Хранилище остаётся файловым и подходит для одного процесса сервера; это не SQL-база
и не многопользовательское распределённое хранилище.

После изменения публичных знаний для GitHub Pages выполните:

```bash
npm run export:knowledge
```

Проверьте получившийся `assistant-knowledge.json` перед commit/push.
Экспортируются только публичные знания и тарифы; ключи, лиды и история исключены.
Серверный режим читает базу сразу, без повторного экспорта.

### Проверки

```bash
npm ci
npm test
```

Тесты используют временные базы и подменённый клиент модели, без обращения к OpenAI
и отправки обращений в CRM. Для полноценной проверки ответов именно модели потребуется
отдельно настроенный сервер с ключом OpenAI. Автотесты проверяют правила, источники
данных, инструменты и API, но не доказывают поведение всех возможных ответов модели.
